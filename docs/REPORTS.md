# 成果物の役割

## `reports/analysis.md`

分析結果を保存する。

- データと対象期間
- 6つのWebサイト運営目的の達成状況
- LP・ブログの分析
- 必要なグラフ・比較表
- 確認した事実
- 原因の仮説
- 判断できなかったこと・追加データ
- KGI・KPIの確認と提案

改善アクション、優先順位、文案、実行計画は書かない。

## `reports/actions.md`

分析結果、公開サイトの確認、Webサイト運営目的、実務上の知見をもとにした、
その時点の改善アクション案を保存する。

- 今回の改善方針
- 提案の起点（データ、サイト実査、目的、実務仮説）
- 対応するWebサイト運営目的
- 現状認識と提案理由
- A / B / C分類と優先順位
- Webサイト内外を含む具体的な実施内容
- 期待する変化と定量・定性の確認方法
- 担当、工数、費用、依存関係、リスク、完了条件
- 計測上の前提
- 推奨する実施順序・進め方
- 人とLLMで検討する事項

このファイルはプロンプトではなく、検討対象となる出力である。その時点の改善提案だけを
記載する。人が内容を修正した場合は、その内容が現在の最新版となる。

## 保存ルール

```text
reports/
  analysis.md
  actions.md
```

このワークフローが生成・更新する利用者向け成果物はこの2ファイルとし、再実行時に
最新版へ置き換える。過去版、月別フォルダ、実行IDは新たに作らない。既存の旧成果物は
分析入力に使用しない。人が修正した場合は修正後を最新版とする。

## 入力

```text
inputs/
  external-events.md  # 今回分へ置き換える
  action-log.md       # 完了済み内容を累積する
```

## 内部作業データ

```text
.analysis/current/
  raw/
  context.md
  manifest.json
  quality-report.md
  content-notes.md
  stage-status.md
```

利用者が内部作業データを整理・編集する必要はない。
