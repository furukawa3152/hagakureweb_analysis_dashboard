# Hagakure Web 分析ダッシュボード

このプロジェクトは、HAGAKUREのWebサイト運営の目的に沿って、GA4、Google Search Console、および公開サイトのデータなどを、データ分析や事業戦略を専門とするAIエージェントが分析し、その結果に基づいた改善アクションを提案する取り組みです。
人とAIがそれぞれの役割を分担しながら、Webサイトおよびコミュニティ運営の改善を継続的に進めるPDCAサイクルを実行することを目的としています。

## 毎月行うこと
人とAIで役割分担は以下のとおりです。また、アクション案（サイトプログラムの変更など）の実施は人が判断別途実施します。
```text
① 対象期間を指定【人】
② 外部イベントとこれまでの実施済みアクションを記入【人】
③ 分析結果とアクション案を作成【AI】
④ アクションを実施【人】
→ 翌月①へ戻る
```

## 最初に見るファイル

| 用途 | ファイル |
| --- | --- |
| 初回セットアップ | [`SETUP.md`](./SETUP.md) |
| 今回の外部イベント | [`inputs/external-events.md`](./inputs/external-events.md) |
| 累積する実施済みアクション | [`inputs/action-log.md`](./inputs/action-log.md) |
| 分析結果 | [`reports/analysis.md`](./reports/analysis.md) |
| 現在の改善アクション案 | [`reports/actions.md`](./reports/actions.md) |

`reports/` に保存するのは、常に最新の `analysis.md` と `actions.md` だけです。
API生データや検証資料は `.analysis/current/` に保存され、通常は確認不要です。

## 初回セットアップ

初めて使うときだけ、次のように依頼します。

```text
SETUP.mdを読み、初回セットアップを案内してください。
```

## 毎月の実行手順

### 1. 外部イベントを今回分へ更新する

`inputs/external-events.md` は、対象期間に数値へ影響し得る出来事だけを書きます。
前回の内容は残しません。

```markdown
# 外部イベント

- 2026-07-10: コミュニティイベントを開催
- 2026-07-18: SNSでブログ記事が紹介された
```

何も無い場合:

```markdown
# 外部イベント

- 2026-07-01 .. 2026-07-31: 特記事項なし
```

### 2. 完了したアクションを追記する

`inputs/action-log.md` は、過去からの実施したアクションの記録を削除せず累積します。

```markdown
# 実施記録

- 2026-07-05: ブログへGA4タグを追加
- 2026-07-20: CTAの文言を変更
```

完了した内容だけを書きます。予定、検討中、未実施のアクション案は書きません。

### 3. 分析を実行する

実行方法は2つあります。

| 方法 | 動作 | 依頼回数 |
| --- | --- | ---: |
| 一括実行 | 分析とアクション提案を続けて行う | 1回 |
| 2段階実行 | 分析結果を確認してからアクションを提案する | 2回 |

#### 一括実行

```text
prompts/RUN_ANALYSIS.mdを読み、Web分析を実行してください。
対象期間: 2026年7月
```

分析と提案の精度を個別に確認したい場合は、次の2段階実行を使います。

#### 2段階実行 — 1回目

```text
prompts/RUN_ANALYSIS_STEP_BY_STEP.mdを読み、段階実行を開始してください。
対象期間: 2026年7月
```

AIはデータを取得し、`reports/analysis.md` だけを作って停止します。

#### 2段階実行 — 2回目

`reports/analysis.md` を確認し、必要なら直接修正してから次を送ります。

```text
prompts/RUN_ANALYSIS_STEP_BY_STEP.mdを読み、次へ進めてください。
```

AIは修正後の分析を正として `reports/actions.md` を作り、停止します。
対象期間、段階番号、ID、保存先を再入力する必要はありません。

## 2つの成果物の違い

### `reports/analysis.md`

データとサイト実査から確認できた事実、目的別の達成状況、原因仮説を記載します。

### `reports/actions.md`

`analysis.md`、公開サイトの確認、コミュニティの目的、実務上の知見をもとに検討した、
改善アクション案を記載します。
各アクション案には、主な提案の起点が明記されます。

```text
データ / サイト実査 / 目的 / 実務仮説
→ 対応する目的
→ 実施内容
→ 期待する変化
→ 定量・定性の確認方法
```

データは状況理解と優先順位付けの参考にしますが、統計的有意差や大きなサンプル数を
提案条件にはしません。データが少ない領域でも、目的との関係と提案理由を説明した上で、
Webサイト改善、広報、投稿支援、地域連携、運営・学習機会づくりなどを幅広く検討します。
施策の規模や期間は一律に決めず、すぐに行う対応、継続施策、中長期の改修を
目的・期待できる効果・負担に応じて提案します。

## 4. 人とAIでアクションを検討する

`actions.md` ができた後は、通常の文章で比較、修正、具体化できます。

```text
reports/actions.mdのアクション案を、今月4時間以内で実施できる順に比較してください。
```

```text
記事末のコミュニティ紹介を今月実施する方向で、具体的な作業手順を作ってください。
```

人とAIは、目的への寄与、期待できる効果、実現可能性、参加者の負担、継続しやすさを
確認しながら、内容・優先順位・実施方法を調整します。最終的に何を実行するかは人が
決定します。

## 5. 人が実行し、記録する

実施するアクションは人が決定します。完了したら `inputs/action-log.md` へ追記し、
翌月の分析で効果仮説と重複提案の防止に使います。

## 保存場所

```text
inputs/                  人が分析前に記入
reports/                 人が読む最新の分析結果と改善アクション案
.analysis/current/       AIが使うAPIデータ・検査・実査メモ
```

| 項目 | 扱い |
| --- | --- |
| 対象期間 | 人が自然な文章で指定 |
| 比較期間 | 直前の同日数を自動計算 |
| APIデータ | 実行時に再取得 |
| 過去版 | 作成しない |
| 実行ID・連番 | 使用しない |
| 人による修正 | 修正後を最新版として扱う |

目的・分析・提案の基準は [`plan.md`](./plan.md)、内部フローは
[`docs/AI_AGENT_ANALYSIS_DESIGN.md`](./docs/AI_AGENT_ANALYSIS_DESIGN.md)、
成果物仕様は [`docs/REPORTS.md`](./docs/REPORTS.md) を参照してください。

実際の分析・提案要件は
[`prompts/RUN_ANALYSIS.md`](./prompts/RUN_ANALYSIS.md) に一つのマスタープロンプトとして
まとめています。`01_ANALYZE.md` と `02_PROPOSE_ACTIONS.md` は、これを2段階で
確実に停止させるための内部実行指示です。

## ダッシュボードを起動する

```bash
pip install -r requirements.txt
streamlit run app.py
```

主な画面:

- 健康診断
- 改善のヒント
- ページ別統合ビュー
- 伸び / 落ち
- 推移
- 検索キーワード
- 流入経路・デバイス
