# 第2段階 — 改善アクションの検討

この段階では、`reports/analysis.md`、公開サイト、Webサイト運営目的、実務知見を
組み合わせ、`reports/actions.md` に改善アクションを提案する。統計的な精度や
データ量だけを提案可否の条件にしない。

## 開始条件

- `reports/analysis.md` が存在する
- `.analysis/current/stage-status.md` が `phase: analysis_complete`
- 人が分析結果を修正した場合は、修正後のファイルを使用する

## 必読

1. `prompts/RUN_ANALYSIS.md`
2. `plan.md`
3. `reports/analysis.md`
4. `.analysis/current/content-notes.md`
5. `.analysis/current/context.md`
6. `.analysis/current/quality-report.md`
7. `inputs/action-log.md`

`RUN_ANALYSIS.md` の「第2段階 — 改善アクションの検討」を省略せず適用する。
必要に応じて `.analysis/current/raw/` も参照する。

## アクション検討の考え方

- データは重要な参考情報だが、提案の唯一の根拠にはしない。
- データが少ない、期間が短い、未計測という理由だけで提案を止めない。
- データ起点、サイト実査起点、目的起点、実務仮説起点の案を幅広く検討する。
- データ上の問いと実査結果が接続している場合は、その対応関係を提案根拠にする。
- Web改修、コンテンツ、広報、編集支援、イベント、地域連携、
  コミュニティ運営、開発・運営学習を対象にできる。
- 短期施策、継続施策、中長期施策を目的と状況に応じて提案する。
- 直接データで裏付けられない案は、その起点、目的との関係、提案理由を明記する。
- 効果確認は定量指標だけでなく、参加者・運営者の反応、負担、学びも使用する。
- 実施済みアクションと同じ内容は再提案しない。発展案なら違いを明記する。

## 実行

1. 次を実行し、前回の `reports/actions.md` を削除する。

   ```bash
   python3 scripts/prepare_analysis_stage.py actions
   ```

2. LP・ブログ×3対象者の目的を確認したうえで、分析と実査から優先する課題・機会を
   選ぶ。目的ごとに案を一件ずつ作るなど、件数を固定しない。
3. A / B / Cと計測・基盤に分類し、優先順位を付ける。
4. Webサイト内の施策と、関連する現実世界の施策を含めて具体化する。
5. 推奨する実施順序と効果確認方法を整理する。
6. `reports/actions.md` を作成する。
7. `.analysis/current/stage-status.md` を次へ更新する。

   ```yaml
   phase: actions_complete
   period: YYYY-MM-DD .. YYYY-MM-DD
   ```

## `reports/actions.md` の構成

1. 今回の改善方針
2. A / B / C分類のアクション一覧と優先順位
3. 各アクションの詳細
4. 推奨する実施順序・進め方
5. 効果確認の方法
6. 人とLLMで検討する事項

`actions.md` にはその時点の改善提案だけを記載し、再実行時は最新版へ置き換える。

## 各アクションの必須項目

- アクション名
- A / B / Cまたは計測・基盤
- 提案の起点: データ、サイト実査、目的、実務仮説
- 対象サイト・対象者
- 対象URLまたは機能と、変更する見出し・本文・リンク・ボタン・ナビゲーション・
  運用工程などの位置
- 対応するWebサイト運営目的
- 現在の状態と、根拠となるデータの期間・指標・値、または実査したURL・観察事実
- 変更後の内容、必要に応じた文言・情報順序・配置・制作物・運用手順の例
- 対象者の理解・判断・行動に期待する変化
- 優先度と理由
- 既存指標を使った定量・定性の効果確認方法、基準値、時期
- 担当、概算人時、必要スキル、費用、依存関係
- 参加者・運営者の負担や留意点
- 完了条件

機械的なIDや連番は使用しない。

## 禁止

- 統計的有意差や大きなサンプル数を提案条件にする
- データ量だけを理由に目的起点・実務仮説起点の案を除外する
- Webサイト改修だけに限定し、関連する現実世界の施策を検討しない
- 対象と変更内容のない「SEO強化」「SNS発信」「CTA改善」「UI改善」
  「内部リンク追加」「モバイル対応」「イベント実施」で終わる
- 実施済みアクションを同じ内容で再提案する
- 現在の改善提案以外の管理欄や過去一覧を `actions.md` に作る
- サイト、計測、コンテンツをこの段階で実際に変更する
- `reports/analysis.md` や `inputs/action-log.md` を変更する

## 利用者への返答

改善方針、優先度の高いアクション案、実施順序、`reports/actions.md` の保存先を
短く返す。実行の最終判断は人が行う。
